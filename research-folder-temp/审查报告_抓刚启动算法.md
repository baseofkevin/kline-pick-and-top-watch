## 0. 结论摘要

**代码实现是对的，但它抓的不是「刚启动」，而是「超跌后首次收复 MA20」。**

我按代码原样回放 18 个周频基准日，得到 **132 只**，与 v2.3 登记的「C2=1% 后 132 只」完全一致；2026-10-14 得 12 只，也与 `result_2026-10-14.json` 一致。说明 `find_start()` / `judge()` / 市值比这条主链路**没有算错**，问题主要在定义和边界条件。

具体分四层：

| 层 | 结论 |
|---|---|
| **实现正确性** | 主链路正确；但有 **4 个会静默改变名单的实现 bug**：K 线截断不校验、缓存键不含参数、`--chg-lo/hi` 本地不复核、非交易日不校验。另有「空结果被当成失败」的可靠性问题。 |
| **定义正确性** | **不符合「刚启动/突破」的通常语义。** 132 只入选股中：**79 只（59.8%）MA60 仍在下行**；**112 只（84.8%）不是 20 日新高**；17 只（12.9%）MA20 仍在 MA60 下方；只有 59 只（44.7%）前 20 日振幅 ≤12%。它更像「下跌趋势里的反弹」筛选器。 |
| **参数事实性** | **`9.5%` 上限是事实错误，不只是保守。** 文档说「覆盖主板涨停」（`K线选股规则_v3.md:101`），但主板涨停约 +10%，9.5% **恰好把主板涨停排除在外**；创业板/科创板 20%、北交所 30% 的强势启动也被腰斩。全市场样本中，**24.9% 的「放量上穿 + 结构合格」事件被这道上限砍掉**（1,667/6,688），其中 977 个落在 9.5%~10.5%，大概率就是主板涨停。 |
| **收益证据** | 91 天缓存、S+1 收盘买入：132 只的 5 日超额中位数 **+0.09%**、10 日 **−0.52%**、20 日 **−3.32%**（n=68）。没有正期望证据，和文档第七节「无显著 alpha」的自述一致。**不要因为 5 日微正就认为有效。** |

**一句话建议**：先把 P0 的实现 bug 修掉；然后把「启动」从「上穿 MA20」改成「**趋势向上 + 箱体收敛 + 放量突破枢轴 + 相对强度 + 市场环境**」的复合事件；如果只想最小改动，至少加上 `MA20>MA60`、`MA60` 上行、20 日新高/箱体、板块无关的涨停识别和 50 日均量基准。

## 2. 程序到底在抓什么

### 2.1 现行定义的逐行还原

`find_start()`（`screen_kline.py:486-512`）：

1. 从基准日 S 往前找，只要 `close > MA20` 就继续，遇到跌破就停；
2. 这一段的第一天就是 `d*`（启动日），`age = S 的索引 − d* 的索引`；
3. 计算 `d*` 的量能倍数 `vcross = vol(d*) ÷ 前 5 日均量`。

`judge()`（`screen_kline.py:515-544`）再检查：

| 条件 | 代码位置 | 实际含义 |
|---|---|---|
| `age ≤ 4` | 519-520 | 启动发生在最近 5 个交易日内 |
| `vcross ≥ 1.75` | 521-522 | 启动日放量 ≥ 前 5 日均量的 1.75 倍 |
| `d*` 当天在横截面池里 | 523-525 | 涨幅 2%~9.5%、当日/5 日主力净流入 >0、非退市、非停牌 |
| `MA20(d*) ≥ MA60(d*)×0.98` | 526-529 | **允许 MA20 低于 MA60 2%** |
| `MA20(d*) > MA20(d*−5)×0.99` | 530-533 | MA20 近 5 日跌幅不超过 1% |
| 非 ST、非次新 | 536-539 | 用 `d*` 当天的标签 |
| `d*+1..S` 收盘都不破 MA20 | 540-543 | 由 `find_start()` 的定义保证，恒真 |

所以它抓的是：**「最近 5 天内，某天放量上穿 MA20，之后没跌破，且当天涨幅 2%~9.5%、有主力净流入」**。

这和文档第一节「放量向上突破 20 日均线」是同一件事；但和交易语境里的「刚启动」**不是同一件事**。

### 2.2 为什么说它不是「启动/突破」

「启动」在趋势交易里通常至少包含四件事：

1. **之前有一段可识别的箱体/整理**（供给被吸收）；
2. **价格突破箱体上沿/枢轴**（不是只上穿一条均线）；
3. **突破日放量**（相对 50 日均量，而不是 5 日）；
4. **大趋势向上**（MA60/MA120/MA200 上行，价格在 52 周高点附近）。

现行规则只做了第 3 条的一半，另外三条都没有。用 132 只入选股和 3,299 个全市场合格事件量化：

| 结构指标 | 132 只入选股 | 全市场 3,299 个合格事件 |
|---|---:|---:|
| MA20 < MA60（仍处死叉） | **17（12.9%）** | **21.2%** |
| MA60 相对 20 日前下行 | **79（59.8%）** | **43.7%** |
| 不是 20 日收盘新高 | **112（84.8%）** | **80.5%** |
| 前 20 日振幅 >15% | **54（40.9%）** | **25.3%** |
| 启动日不是 ±2 日内最大量日 | — | **28.6%** |

> 注：132 只中前 20 日振幅 >12% 的有 73 只（55.3%），>15% 的有 54 只（40.9%）；中位数 12.71%，p90 25.51%。

**解读：**

- **六成入选股的 MA60 还在下行**。这不是「启动」，是「下跌途中的反弹」。真正的 Stage 2 启动，MA60 至少应走平/上行。
- **八成以上不是 20 日新高**。也就是说，价格连最近一个月的最高点都没过，谈不上「突破」。
- **近三成事件的放量日不是 `d*`**。因为 `d*` 被钉死在「上穿 MA20」那天，而真实的放量/资金主攻日可能早一天或晚一天；把日频条件绑在 `d*` 上会系统性错配。
- **12.9% 的入选股 MA20 仍在 MA60 下方**，因为 `C3_RATIO=0.98` 允许 2% 的「死叉容忍」。这与「启动」语义直接冲突。

#### 2026-10-23 的 5 只就是现成例子

`csv/选股_2026-10-23.csv`：

| 代码 | 名称 | 距启动 | 量能 | 涨幅 | MA20÷MA60 | 距MA20 | 距MA60 |
|---|---|---:|---:|---:|---:|---:|---:|
| sz300886 | 华业香料 | 0 | 5.59 | 8.58% | **0.9894** | +0.95% | −0.12% |
| sz002031 | 巨轮智能 | 0 | 1.98 | 5.80% | **0.9879** | +1.75% | +0.52% |
| sz002051 | 中工国际 | 0 | 1.88 | 3.71% | **0.9878** | +1.10% | −0.13% |
| sz002315 | 焦点科技 | 0 | 1.88 | 6.88% | **0.9901** | +5.70% | +4.65% |
| sh603677 | 奇精机械 | 2 | 6.81 | 4.26% | 1.0437 | **+13.46%** | **+18.42%** |

- 前 4 只 MA20 都在 MA60 下方（0.9878~0.9901），是典型的「下跌后反抽」；
- 奇精机械在 S 日已经高于 MA20 **13.46%**，高于 MA60 18.42%，`age=2`，属于「启动后追高」，规则没有任何「不过度延伸」约束；
- 华业香料流通市值 10.99 亿、换手 13.36%、量能 5.59 倍、涨幅 8.58%，是典型的小盘题材脉冲；它的市值比 0.201% 刚好压线通过 0.2% 门槛。

这些票可能是好票，但它们不是同一类「刚启动」形态；名单把「反抽」「突破」「追高」混在一起，后续人工研究很难用同一套标准处理。

### 2.3 9.5% 上限：事实错误，且砍掉最强的一批

文档 `K线选股规则_v3.md:101` 写：

> 放宽到 9.5%（**覆盖主板涨停**）池子 +17%，名单保留 86%

这句话不成立：

- 上海主板/深圳主板一般股票涨跌幅 **10%**（`上海证券交易所交易规则`：涨跌幅比例 10%，四舍五入到最小变动单位）；
- 创业板（2020-08-24 起）、科创板 **20%**；
- 北交所 **30%**。

主板涨停收盘的 `ChangePCT` 通常在 **+9.9%~+10.1%**（受四舍五入影响），**>9.5%**。所以 `ChangePCT <= 9.5` 恰好把主板涨停排除；创业板/科创板 9.5%~20% 的强势启动也被砍掉一半；北交所更不用说。

全市场 287 个交易日（2025-08-05~2026-10-14）、4,655 只股票的统计：

| 口径 | 数量 |
|---|---:|
| MA20 上穿事件 | 56,225 |
| 其中放量 ≥1.75× | 13,747 |
| 其中涨幅 2%~9.5% | 9,579 |
| 放量 + 结构合格（MA20≥0.98×MA60） | 6,688 |
| 其中涨幅 ≥9.5% | **1,667（24.9%）** |
| ├ 9.5%~10.5%（大概率主板涨停） | **977** |
| └ ≥10.5%（20%/30% 板） | 690 |
| 其中涨幅 <2% | 407（6.1%） |

也就是说，**每 4 个「放量上穿 + 结构合格」事件，就有 1 个被 9.5% 上限直接删掉**；被删的恰恰是强度最高的一批。这不是「保守」，是**把策略最想抓的样本系统性排除**。

> 口径说明：上表 6,688/1,667 是 287 日全缓存；若只看 18 周窗口（2026-06-01~2026-10-14），是 **2,580 个事件、697 个 ≥9.5%（27.0%）**。不要把 6,688 说成“91 个交易日”。

更合理的做法不是「一刀切 9.5%」，而是：

1. 按板块计算涨停价：主板 10%、创业板/科创板 20%、北交所 30%（ST 另算）；
2. 把「收盘接近涨停/一字板」单独标记为 **不可买/观察**，而不是从池子里静默删除；
3. 对可买的强势日，允许涨幅到「涨停价 − 0.2%」左右；对 20% 板，不要把上限压在 9.5%。

### 2.4 2% 下限也在误伤「安静启动」

`CHG_LO=2.0` 要求上穿日至少涨 2%。但真实的启动可以是：

- 前一天已经放量突破，次日只是小幅上穿 MA20（+0.5%~1.5%）；
- 一字板/大幅高开后，MA20 上穿发生在涨幅很小的「承接日」；
- 低波动大盘股的突破日涨幅本来就只有 1%~2%。

样本中「放量 + 结构合格但涨幅 <2%」有 **407 个（6.1%）**。这不是最大问题，但它和 9.5% 上限一起，把「启动日」定义成了一个很窄的涨幅区间，而不是「形态 + 量能」事件。

### P0-1 K 线截断不校验（会静默剔除合格股）｜v2.6 已修

`get_kline()`（`screen_kline.py:263-329`）只检查「代码是否在 `km` 里」，不检查「最后一根 K 线是不是 S」。如果批量接口在某一批只返回前 400 行（`download_history.py:308` 明确记录过这个现象），某只股票可能只拿到截至几周前的数据：

- `c in km` 为真 → 不会进入 `missing` 补取；
- `find_start()` 找不到 S → 返回 `K线无 S 数据`；
- 该股被静默剔除，拒绝明细看起来完全正常；
- 更糟的是，坏数据已经 `jdump` 进 `kline_*.json`，**同日重跑不会重取**；v2.5 只修了「补取只写 1 根」的写入路径，没有清理已经落盘的坏缓存。需要删除该 span 的 `kline_*.json` 或加 `--refresh` 才能恢复。

`download_history.py` 已经有这个校验：

```python
trunc = [c for c in codes if km.get(c) and km[c][-1][0] != end]
```

`screen_kline.py` 没有。建议直接搬过来，并在 `find_start()` 前加一道：

```python
bad = [c for c in pool if km.get(c) and km[c][-1][0] != S]
if bad:
    raise RuntimeError(f"K线末日≠{S}：{bad[:5]}…（先补取/刷新，勿产出名单）")
```

这是 v2.5 修复「补取只存 1 根」的同一类问题，但 v2.5 只修了「完全缺失」，没修「部分截断」。

### P0-2 缓存键不含参数，`--chg-lo/hi` 实际不生效｜v2.6 已修

`get_cross()`（`screen_kline.py:221-234`）的缓存键只有日期：

```python
path = os.path.join(DB, f"cross_{day}.json")
if os.path.exists(path) and not refresh:
    return jload(path, [])
```

而 `judge()` **没有在本地复核 `ChangePCT`**。后果：

- 先按默认 2%~9.5% 跑一次，缓存 `cross_*.json`；
- 再跑 `--chg-lo 5 --chg-hi 7`，`get_cross()` 直接读旧缓存，`judge()` 也不检查涨幅；
- 结果仍然包含 2%~5% 和 7%~9.5% 的股票，**命令行参数完全失效**，而且不会报错。

同理，修改 `CROSS_TPL`（比如增删字段）后，旧缓存也不会失效。

修复两件事：

1. 缓存键加入参数/模板指纹：`cross_{day}_{sha1(CROSS_TPL+lo+hi)[:8]}.json`，或参数变化时强制刷新；
2. `judge()` 本地复核 `ChangePCT`（以及 `MainNetFlow`、`MainNetFlow5D` 的符号），不要完全信任服务端和缓存。

### P0-3 服务端条件本地不复核（信任边界太宽）｜v2.6 已修

`judge()` 只用 `if row0 is None: reject "未通过日频条件"` 来判断 d* 当天是否满足涨幅/资金/退市/停牌。也就是说，**所有日频条件都外包给了服务端表达式 + 缓存**。项目自己已经在文档里记录过服务端会「静默返空/字段随表达式来去」，这里却把最关键的门槛完全交给它。

建议在 `judge()` 里补：

```python
chg = fnum(row0.get("ChangePCT"))
nf  = fnum(row0.get("MainNetFlow"))
nf5 = fnum(row0.get("MainNetFlow5D"))
if chg is None or not (chg_lo <= chg <= chg_hi):
    return False, "③ 启动日涨幅不在区间"
if nf is None or nf <= 0:
    return False, "③ 启动日净流入≤0"
if nf5 is None or nf5 <= 0:
    return False, "③ 5日净流入≤0"
```

如果 `IsDelisted`/`Ifsuspend` 也在返回里，一并复核；缺字段就 `raise`，不要静默通过。

### P0-4 非交易日 `--date` 会产出空名单｜v2.6 已修

`main()`（`screen_kline.py:576-584`）直接：

```python
S = a.date or days[-1]
hist = [d for d in days if d <= S]
```

如果用户传了周末/节假日，`S` 不在 `days` 里，`find_start()` 永远找不到 `x[0] == S`，所有股票都报 `K线无 S 数据`，程序以 0 退出并写出一份空 CSV。**这是静默假阴性。**

修复：

```python
if S not in days:
    raise SystemExit(f"基准日 {S} 不是交易日；最近交易日是 {max(d for d in days if d <= S)}")
```

### P0-5 空结果被当成失败（标签分页/横截面空列表）

`retry()` 原来用 `if r:` 判断成功，**空列表 `[]` 会被当成失败**。这会带来两个问题：

1. `get_labels()` 分页正好是 500 的整数倍时，下一页返回 `[]` → 重试 4 次 → `raise RuntimeError("排除集拉取失败")`，整次运行中止；
2. 某个分桶当天恰好 0 只（例如 5 日内无新股）时，首屏 `[]` 也会被当成失败。

**v2.6 的修法（有意保守）：**

- `retry(..., allow_empty=True)` 只在「空结果本身合法」时使用；
- 标签分页**第 2 页起**允许空页，视为正常结束；
- **首屏为空仍判失败**——不能把接口故障当成「没有次新股」，否则会漏剔次新股；
- **`get_cross()` 空结果仍判失败**——项目已记录「历史日期接口会静默返空」，把空当成「当天 0 只」会产出假阴性名单。

所以这项只修了「分页空页」这个确定性 bug；首屏空/横截面空的保守行为保留，属于有意的可靠性取舍。

### P0-6 `get_kline()` 只存 3 个字段（阻断所有质量过滤）｜v2.6 已修

`screen_kline.py:280-281`：

```python
km.setdefault(c, []).append((r["date"], float(r["last"]), float(r["volume"])))
```

API 返回的 `open/high/low/amount/exchange` 被丢弃。导致无法实现：

- 收盘位置（`close` 是否在当日 high 附近）；
- 一字板/涨停封死识别；
- ATR / 波动收缩；
- 成交额/换手率流动性门槛；
- 跳空与次日开盘可成交性。

建议把 bar 改成 dict 或 6 元组（date, open, high, low, close, volume, amount），并同步改 `find_start`/`judge` 的索引方式。**这是后续所有改进的前提。**

### P1-1 `C3_RATIO=0.98` 允许 MA20 低于 MA60

`screen_kline.py:77` / `528`。这不是实现错误，是设计选择；但它与「启动」语义冲突。132 只中 17 只（12.9%）MA20<MA60。建议至少改成 `MA20 >= MA60`，最好再加 `MA60 > MA60(20日前)`。

### P1-2 只检查 `d*` 当天的 ST/次新

`judge()` 用 `st_by_day[d0]` / `new_by_day[d0]`（`536-539`），没检查 S 日。若 d* 之后被 ST，或 S 日已停牌/退市，名单仍会保留。建议 S 日再查一次，且把「S 日涨停/一字板」标为不可买。

### P1-3 市值比分母用 S 日，分子用 d* 日

`main()`（`screen_kline.py:662-667`）用 `d*` 的 `MainNetFlow` 除以 S 日的流通市值。文档 3.2.3 已承认这个口径问题；`age=4` 时分母滞后 4 天，小盘股一周内市值变化可能超过 10%，足以让 0.2% 的阈值翻转。建议用 `mv_<d*>` 或 `quote --date d*` 的分母。

### P1-4 `find_start()` 的 51 日上限不是真上穿

`for j in range(i, 19, -1)`（`498`）最多回溯 51 天；如果一只股票连续 51 天都在 MA20 上方，`ci` 会停在索引 20，而 `close[19]` 可能也在 MA20 上方——此时 `d*` 并不是「上穿日」。因为 `age` 会 >4 被 ⑦ 拒绝，**不会产生假阳性**；但语义上应补一句 `bars[ci-1].close <= MA20(ci-1)`，否则未来放宽 N 时会出错。

### P1-5 「启动后未跌破 MA20」⑥ 恒真

`judge()` 的 540-543 行与 `find_start()` 的回扫是同一件事，文档 2.2 已承认它「阻断 0 只」。保留无害，但不要把它当成独立风控；真正需要的是「启动后回踩不破 **启动日低点/箱体上沿**」，而不是 MA20。

### P1-6 没有流动性/板块/可买性约束

- 没有最低成交额/换手率门槛：10 亿流通市值的小票，日成交几千万也能入选；
- 没有排除北交所（30% 涨跌幅、流动性差异大）；
- 没有排除 S 日涨停/一字板（买不进）；
- 没有排除 `close` 已经远离枢轴（奇精机械 +13.46% 就是例子）。

对一个以「修改登记规范」为荣的项目，这些不是排版问题，是**复现口径问题**。建议一次性修正，并在版本表登记。

### P2-2 收益验证缺失

文档第七节已承认「所有变体相对沪深300 的按日超额都不显著（最高 |t|=1.78）」。这比大多数策略诚实；但目前：

这些不改变「选股名单」，但决定了「这套规则是否值得继续投入」。详见第 6 节。

### 4.1 一个关键的概念区分

**「上穿 MA20」是均值回归/趋势转折信号；「突破枢轴」是动量/突破信号。** 两者的失败模式相反：

- 上穿 MA20 在震荡市里反复 whipsaw；在下跌趋势里抓到的是反抽，反抽结束后继续跌；
- 突破枢轴在假突破时亏得快，但需要箱体、量能、市场环境共同确认。

现行规则把两者混在一起：用「上穿 MA20」定位事件，却用「涨幅 2%~9.5% + 放量 + 资金流入」去要求它像突破。结果是**既没有突破的确认，也没有反抽的赔率优势**。这是我认为最需要改的地方。

## 6. 改进建议

### 6.1 P0：先修正确性（不改策略也能做）

| # | 改动 | 具体做法 |
|---|---|---|
| 1 | **K 线完整性校验** | `km[c]` 必须存在、`km[c][-1][0] == S`、`len(km[c]) >= MIN_HISTORY`；否则补取/报错，不得静默剔除 |
| 2 | **缓存键含参数** | `cross_{day}_{hash(CROSS_TPL, lo, hi)}.json`；或任何参数变化自动 `--refresh` |
| 3 | **本地复核服务端条件** | `judge()` 检查 `ChangePCT`、`MainNetFlow`、`MainNetFlow5D` 符号；缺字段 `raise` |
| 4 | **校验基准日** | `S in days`，否则报错并给出最近交易日 |
| 5 | **区分空结果与失败** | `retry()` 改为返回 `(ok, rows)`；空列表对 label/cross 是合法结果 |
| 6 | **落盘 OHLC/amount** | bar 改为 `(date, open, high, low, close, volume, amount)`；为后续 ATR/收盘位置/流动性做准备 |
| 7 | **修文档** | C2 0.01、v2.5、argparse v1、9.5% 依据；在版本表登记 |

### 6.2 P1：重定义「启动」——两条路线

#### P1-A（v2.7 已落地上下限，可买性待做）：统一区间 0.5%~20.5% + 可买性 0.5%

9.5% 是**候选池硬截断**，不是普通过滤器：股票没进池，后面的趋势/箱体条件再完美也补不回来。18 周实测放宽到 30% 后名单 **132 → 236（+104）**；新增 104 条中 S 日封死/一字 28 条（26.9%），S+1 仍封死仅 3/85（3.5%）。建议：

- **候选池统一区间 `CHG_LO=0.5`、`CHG_HI=20.5`**（上限覆盖主板 10% 与创业板/科创板 20% 的涨停，含 20.0x 四舍五入；当前数据无北交所，若纳入北交所上限改 30.5；下限 0.5 排除平盘，0 也可、名单相同）；
- **可买性统一容差 0.5%**：`close >= 涨停价-0.005` 算封死；距涨停 ≤0.5% 算贴近/不追；涨停价本身按 10/20/30 板块计算；
- S 日封死/一字进观察池，不进入可买名单；S+1 开盘/收盘涨停加标注。

这样既“按板块识别涨停”，又只用一个通用上限。新增 104 条的前瞻收益尚未验证，不能把扩池直接当成收益改善。

**落地状态**：v2.7 已改 `CHG_LO=0.5`、`CHG_HI=20.5`、`CROSS_CACHE_VERSION=2`，并用 2026-10-23 重跑验证（19 只，参数表显示 `[0.5, 20.5]`）。观察池/涨停状态列尚未写入。

#### 路线 A：最小改动，保留「上穿 MA20」哲学

如果不想推翻现有框架，至少加四道：

1. **趋势**：`MA20 >= MA60` 且 `MA60 > MA60(20日前)`；最好再加 `close > MA120`；
2. **箱体/新高**：`close(d*) >= max(close[d*-20:d*])` **或** 前 20 日振幅 ≤12%；
3. **量能基准**：`vol(d*) >= 1.5 × mean(vol[d*-50:d*])`（IBD 口径 40%~50% above 50-day avg），而不是 1.75×5 日；
4. **市场环境**：沪深300/中证1000 在 MA200 上方，或全市场宽度 >50%；不满足时只观察不选。

这会显著减少名单（估计 132 → 30~50），但每一只都更像「启动」。建议把「上穿 MA20」保留为**观察池**，另设「突破池」，不要混在一张表里。

#### 路线 B：推荐——改成「箱体突破 + VCP + 趋势 + RS + 市场」

把「启动」定义为一个**多条件同日共振**事件：

| 维度 | 建议起点（不是优化值） |
|---|---|
| 股票池 | 非 ST、上市满 3 年、非北交所（或单列）、流通市值 20~300 亿、20 日均成交额 ≥1 亿 |
| 大趋势 | `close > MA60 > MA120`；`MA60` 20 日上行；`close` 在 52 周高点 25% 内 |
| 相对强度 | 个股 60 日收益在全市场/同行业前 30%（RS≥70 的代理） |
| 箱体 | 前 20~60 日振幅 ≤12%~15%，或 ≤1.5×ATR20；`ATR20/ATR60 < 0.85`；突破前 5 日量能 <0.8×50 日均量 |
| 触发器 | `close > max(high[d*-20:d*])`（枢轴）；`close` 位于当日振幅上 1/3；`vol >= 1.5×50日均量`；涨幅 3%~涨停价−0.2%（按板块） |
| 可买性 | 排除一字板/收盘封死涨停；`close <= pivot×1.05`（不追高超过 5%） |
| 市场 | 指数 >MA200 或宽度 >50%；否则空仓/只观察 |
| 资金 | 主力净流入降级为**加分项**，不做硬门槛（口径不透明、易被单笔大单扭曲） |
| 出场 | 跌破枢轴/最近收缩低点，或 −7%~−8%；10/20 日时间止损 |

这套规则不是「一定赚」，但它至少让「启动」的语义自洽：**先有趋势，再有收敛，再有放量突破，且买点不追高**。

### 6.3 P2：验证体系（比继续调参更重要）

1. **Point-in-time 全市场**：包含退市/ST/停牌股票，避免幸存者偏差；当前 4,655 只 vs 实际 5,000+，缺口可能正是失败样本。
2. **Walk-forward**：用 2024~2025 调参，2026 留出；或滚动 12 个月训练 / 3 个月测试。不要在同一段 18 周上反复改 C2、基因阈值。
3. **成本与交易约束**：佣金 ~0.025%×2、印花税 0.05%（卖出）、滑点 0.1%~0.3%；T+1；涨停/一字板不可买；停牌不可卖。
4. **基准**：沪深300、中证500、中证1000、等权全市场、行业中位数；报告超额、胜率、盈亏比、最大回撤、换手率。
5. **显著性**：Block bootstrap / Deflated Sharpe；记录「试过多少个参数组合」，按试验次数折旧。以现在 18 周、8+ 参数的规模，任何 |t|<2 的结果都不应被当作证据。
6. **先纸面跟踪**：至少 3~6 个月、覆盖不同市场状态，再决定是否投入真金。

### 6.4 如果只想做一件事

**v2.7 已把 `ChangePCT` 区间从 [2, 9.5] 改成 [0.5, 20.5]**；下一步加 0.5% 的涨停距离/封死判定与观察池。它修的是上游候选池：9.5% 直接删股票，后面的趋势/箱体只能过滤、不能补回。旧表“9.0→110、9.5→112 只差 2 只”是 `[2,9.5]` 截断池内的局部斜率，不能外推到 20.5；新池重放见 P1-A 研究 2.4。18 周实测上限这一步恢复 **104 条**（132→236），下限从 2% 降到 0.5% 再增 **5 条**（236→241）；新增里约七成 S 日可买；这是“先止血”。

第二步再做趋势闸门（`C3_RATIO=1.00` + `MA60` 20 日上行）。它解决的是“别把反抽叫启动”，但只能对已经进池的股票做减法。两步的顺序不要反：先保证候选池完整，再谈信号纯度。
